# スラポン共通手順・共有デザイン

正規の顧客キットと組み合わせる共有部分です。公開リポジトリだけから制作を開始しません。

- `compatibility.json`：顧客キットの対応世代から参照ブランチを選ぶ対応表。
- `SKILL.md`、`references/`：共通の制作手順。
- `standard.md`：Standardの適用手順。寸法の正本は共有HTML。
- `design-systems/{standard,company,serif}/index.html`：共有デザインの唯一の編集元。
- `design-systems/*/runtime/`：Company/Serifのダミー設定による生成済み確認用ビュー。編集元ではありません。
- `assets/design-patterns/`：構図の参考資料集。
- `scripts/`：顧客キットの照合、対応版の取得、素材取得、検査。
- `licenses/registry.json`：ランダムなライセンスID・有効状態・照合用ハッシュだけの一覧。

## 改善の配信と大幅更新

現在は対応世代1を`main`へ向けています。新しい案件の開始時に、その時点の対応コミットを取得します。
案件内では同じコミットを再利用し、途中でルールや素材を最新版へ差し替えません。

世代2を導入する際は、まず現在の互換版を`v1`ブランチへ残し、世代1の参照先を`v1`へ切り替えます。
その後、世代2を`main`へ追加します。`v1`にも必要な互換改善を反映できます。
対応世代は購入者キットの読込契約であり、個々のデザインや顧客設定の版番号とは別です。
対応表のスキーマ1とその取得場所は、旧キットも読み続けられるように保持します。

## デザインと顧客差分

共有HTMLと生成仕様に、キット内の明示的な差分を重ねます。顧客の配色・正式ロゴ・ロゴ配置・
縦透かしなどは顧客側が所有します。共通寸法の更新で顧客の調整をリセットしません。
Company/SerifへStandardの座標を適用しません。既存の採用済み資料は自動変更しません。

## 照合の範囲

キット内のランダムコードを、顧客ID・対応世代・デザイン種別に結び付けてハッシュ照合します。
コードはローカルに保持し、このリポジトリへ登録・送信しません。照合できなければ正規入口は停止します。
公開ファイルの閲覧や、コードを含むキットのコピーを防ぐDRM・サーバー認証ではありません。

## 公開前の検査

共有原本を変更したら制作管理側の`tools/export_shared_designs.py`で仕様とランタイム見本を生成します。
`python3 -m unittest discover -s tests`で対応版取得・差分適用・照合・素材検査を確認します。
顧客名、顧客ロゴ、コード原文、注文・入金情報、個人の絶対パスを公開しません。
