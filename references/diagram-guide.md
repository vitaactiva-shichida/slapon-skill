# 情報の関係から図解を選ぶ

新規構成と構図変更で読む。[メッセージ設計](message-design.md)で主張と根拠を整理してから、図で何を伝えるかを一文にする。型の名前や項目数だけから考え始めない。

## 方向性を決める

| 伝える関係 | 候補の方向性 | 意味の確認 |
| --- | --- | --- |
| 違い・共通点 | comparison、overlap | 比較する観点と条件を揃える。重なりは実際の共通部分に対応させる |
| 順序・経緯・計画 | process、timeline、roadmap、schedule | 順序と期間、実績と予定を分ける |
| 全体と部分・所属 | hierarchy、organization、scope、layer、composition | 所属、包含、機能、数量の構成比を混同しない |
| 条件判断・分岐・合流 | decision、flow | 条件、接続先、分岐の意味を明示する |
| 原因・施策・結果 | causality、equation | 根拠のある作用だけを矢印で結び、計算式の単位を揃える |
| 相互関係・領域 | relationship、matrix、group | 中心を置く理由、二軸の定義、グループの基準を持つ |
| 循環・体験の変化 | cycle、journey | 戻り先や主体、時間の向きを原稿に対応させる |
| 成長・規模・増減 | growth、change、ranking | 視覚的な大小と定量比率を区別し、値・基準を示す |

方向性は検索の入口。カタログの`use_when`と`cautions`で個々の型を判断する。該当しないものを無理に使わない。元から指定・採用された構図は、その拘束範囲を優先する。

## 図の構造とページ配置を分ける

循環図は図解の部品、その横に補足欄を置くのはページ全体の組み立て。図解を本文の一部に置くこともできる。すべての図へタイトル帯や注記欄を追加せず、ページ共通の部品は顧客の定義を使う。

顧客の固定枠・安全領域を確保し、その内側で構図を決める。原稿を箱へ入れる前に、主役、根拠、補足、読み順、接続を整理する。項目が等価なら揃え、役割が異なるなら面積・位置・強弱で区別する。説明文の長さだけで図の意味を変えない。

[見本の検索](design-patterns.md)で候補を見てから、図の領域・要素数・配置を確定する。採用済みの局所修正なら再検索を省略できる。参考図の形や個数に合わせて原稿を削らない。

## 図が暗黙に伝える意味を照合する

- 矢印は順序・移動・作用など、何の方向かを決める。時間の前後を因果へ置き換えない。
- 線は接続、囲みはまとまり、重なりは共通部分や遮蔽として使う。原稿にない所属や共通点を加えない。
- 仮説・予定・可能性は文字でも示し、破線や色だけへ押し込めない。
- 中心ノードを置く理由がない場合は、すべてを中心へ集めない。関係が等価な項目を不要な階層にしない。
- 数量を面積や長さで示すならデータから計算する。成長円などの見本は、そのままでは数値比例でない場合がある。[データ確認](chart-integrity.md)を併用する。
- 段落を箱へ入れただけの図にせず、短いラベルと配置だけでも関係が読めるか確かめる。

構成の判断を[構成記録](diagram-plan.md)へ残す。図の意味、線の始終点、原稿との対応、変更する箇所を確認して画像工程へ渡す。図として描けたことと、主張を事実確認できたことは別に記録する。
