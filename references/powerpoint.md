# 採用画像を、編集可能なPowerPointに再構成する

採用画像の見た目を保ちながら、文字・図形・画像を編集できる部品として組み立てます。画像の採用と進行確認は[制作フロー](workflow.md)に従い、この章では再構成に必要な処理と検証を行います。

### 入力と再現の基準

採用画像、正しい原稿、共通の必須条件（顧客HTMLの該当定義）・ページ固有の設定（顧客HTMLの該当定義）、使用素材（顧客HTMLの該当定義）を確認します。ユーザーの明示指示・正しい原稿・必須条件と承認済みの共通素材を優先し、それ以外は採用画像の配置・比率・質感を再現します。推奨値を理由に見た目を一律に変更しません。

生成画像の誤字・重複・未承認の追加情報は原稿に戻します。共通素材への置き換えなど、採用画像から意図して変える点を記録し、未解決の衝突だけ確認します。

### 1. SVGにする範囲と編集単位を先に定義する

**素材制作の前に、ページを「PowerPoint標準部品」「独立SVG」「独立画像」に分ける。**ヘッダー・フッター・タイトル・リード文・ページ番号はPowerPointで作る。SVGは図解の中で精密な輪郭・重なり・固有形状を保持する必要がある部品に限定する。図解の箱・矢印・円・文字も、同等に再現できるならPowerPointで作る。SVGが必要な箇所がなければ作らない。既定の一体背景に関する下表の例外は保持する。

全ページSVGや文字入り図解SVGを作ってから分解しない。各領域の分類、SVG対象の範囲・理由、別テキストにするラベル、素材判断A/B/Cを記録してから、必要な素材の制作に進む。

| 部品 | 基本の形式 | 判断のポイント |
| --- | --- | --- |
| 文字・数字 | テキスト | 原稿を正として書体・サイズ・改行を調整 |
| 帯・円・罫線・矢印 | PowerPointの図形 | 編集・整列しやすくする |
| アイコン | 独立したSVG | 元の特徴を保持。内部の編集性は別途確認 |
| 写真・質感・複雑な装飾 | 独立した画像 | 文字を混ぜず、比率と透明部分を確認 |
| 固定の帯＋装飾 | 一体の背景画像も可 | 常に一体で使う場合。タイトルは別にする |
| 表・数値グラフ | 必要に応じてネイティブ表・グラフ | 数値と編集要件を先に確認 |

元画像の実際の幅・高さを記録し、各部品にID、役割、範囲[x,y,幅,高さ]、重なり順、出力形式、編集単位、素材パスを付ける。

文字、背景、装飾、アイコン、写真、線、矢印などを分ける。範囲は所在の指定であり、透明な切り抜き境界ではない。

[部品一覧のひな型](parts-record.md)を案件の作業先へコピーし、制作記録の正本にします。既存の同等の記録があれば追記し、二重管理しません。分類と再現範囲は素材制作前に残し、実装中に寸法・接続・パスを更新します。完成PPTXから後で抽出した一覧だけを、事前の判断記録の代わりにしません。番号付き枠の確認画像は必要に応じて作成します。

矩形範囲だけでなく、再現に必要な特徴も記録する。具体的には、中心位置、縦横比、要素間の間隔、整列、角丸半径、曲線の曲がり方、線幅と端点、色の濃淡、透明度、グラデーションの方向、文字の改行・太さ・行間・内側余白を対象にする。

### 2. 再利用・調整・新規作成を決める

各部品について、ブランドキットの素材一覧・承認済みの共通パーツ・過去の作成物を照合する。AIが意味、形状、配色、比率、背景の透明性、品質、編集要件を確認し、以下に分類する。

| 判断 | 処理 |
| --- | --- |
| A | そのまま再利用。条件に合う既存素材を参照し、新規生成や再トレースを行わない。位置・縦横比を保ったサイズ変更は配置時に行う。 |
| B | 既存素材を調整。適合する素材があり、色や余白、形式・互換性などの限定的な変更だけが必要な場合。元ファイルを保ち、必要な差分だけを別版にする。 |
| C | 新規作成。適合する素材が存在しない、または既存素材の調整では用途・品質を満たせない場合のみ行う。 |

部品一覧に「振り分け、参照素材ID・パス、適合を判断した理由、必要な変更、新規作成する理由」を記録する。候補がなければ「該当なし」と明記する。

同じ部品を複数箇所で使う場合は一つの素材を共有する。生成画像の微妙な形の揺れだけを理由に、承認済みの共通素材を作り直さない。一方、意味の異なるアイコンを、既存素材があるという理由だけで流用しない。

### 3. 必要な素材だけ準備する

Aは元の素材をそのまま使用する。Bに限って調整を行い、Cに限って新規生成・SVG化・切り出しを行う。SVGの代替PNGなど互換性のための派生ファイルは、既存のSVGから作成し、デザイン自体は再生成しない。

#### アイコン・SVGの形状を整える

アイコンのSVG化では、シルエット・比率・配置・線幅・負の空間・重要な細部を保ち、画像由来の微小な凹凸だけを整える。意味を解釈した描き直しは別案として保存する。

元画像の濃淡や半透明の重なりが見た目に寄与する場合は保持する。無条件に単色化したり、特定の色数へ統一したりしない。色の整理は、元の特徴を維持できる範囲で行う。

ノイズ除去の前後を拡大と実使用サイズの両方で比較する。光線、細線、小さな穴、ハイライトなど意味のある細部まで消していないか確かめる。

連続した質感やグラデーションをSVGで十分に再現できない場合は、独立した高品質画像として残す選択肢を検討し、編集できる範囲を明示する。無理なベクター化で見た目を劣化させない。文字は別に保持する。

#### 背景から編集対象を分離する

文字と重なった装飾を矩形のまま切り抜かない。文字を除去し、隠れた背景を必要に応じて再生成する。

編集可能なラベルは、文字とラベル背景の塗り・枠・影をまとめて背景から除去し、後からテキストと図形として再構築する。写真と色調・ぼかし・淡いグラデーションが一体の背景なら、一枚の画像に残してよい。

背景を再生成する場合は、被写体の位置・形・数、余白、色調、ぼけを保持し、文字やラベルの下だけを自然に補完する。単色の矩形で隠す方法や、文字を含む完成画像を背面に残す方法にしない。既存の背景原本があれば再生成せず使用する。

透過生成が崩れる場合は、固定の背景帯と一体で生成する方法も検討する。

素材の縦横比を維持する。画像を歪ませて領域に押し込まない。重要部分を切るトリミングは調整または再生成する。

背景の文字・ラベル除去や補完が必要なら、[背景分離の具体例と指示](background-separation.md)を全文読んでから実行します。既存の背景原本があれば再利用します。

### 4. PowerPointに組み立てる

スライド全体の完成画像を背面に残して文字や図形を重ねる構成にしない。部品を移動・削除した際に同じ絵や文字が下から現れないようにする。

背景、装飾、図形、文字の順序を部品一覧に従って配置し、関係する部品は実用的な単位でグループ化する。部品とグループには名前を付け、グループ内でもラベルやアイコンを個別選択できる状態を保つ。

対向する2本の矢印には異なる端点と向きを持たせ、書き出し・再読み込み後にも重ならないか確認する。カスタム接続点を使用環境が再現できない場合は接続方法を修正する。必要なら各端点に透明・無線の小さなアンカー図形を置き、ノードと同じグループに含める方法を検討する。アンカーは互換性のための選択肢であり、すべての図へ強制しない。いずれの方法も、ノード移動による追従を実際に確認する。

単純なアイコンや図解も、内部編集が必要なら形と文字を分けて再構築する。接続線は始点・終点と接続位置を持たせ、ノードを移動した際に追従するかを検証する。SVGのまま保持する部品は、その内部編集の制約を記録する。

全体画像の座標から出力スライドへ換算し、参照pxとPowerPointのptを混同しない。

採用画像がW×H px、出力スライドがSx×Sy ptなら、xと幅はSx÷W、yと高さはSy÷Hで換算する。ライブラリやHTMLの参照座標を使う場合は、その参照キャンバスから別に換算し、採用画像の寸法と混ぜない。縦横の倍率が一致しない場合は歪ませず比率・配置を見直す。

書体は作成ライブラリだけでなく、表示先のPowerPointでも利用できるか確認する。書体名がPPTX内にあることや、作成時の描画が正しいことでは代替書体を検出できない。代替表示ならキット内の正規フォントの導入可否を確認し、必要な許可の範囲で対応する。必要ならアプリを開き直して再確認する。無断で別書体へ変更せず、導入・埋め込みの有無と他PCでの条件を記録する。

文字の書体・太さ・字幅・行間・内側余白を明示する。まず採用画像の文字サイズと改行に合わせ、実際の書体で幅と高さを測って調整する。中央揃えと左揃えも原画像を確認する。

置き換え書体では、同じサイズ指定でも字幅が変わる。欠けた部分だけを局所的に調整し、全文や全ページを一律に縮小しない。原稿修正に伴う改行変更は意図した差分として残す。

円・楕円・角丸長方形・カプセル状の帯を区別し、図形の既定値に任せず角丸や縦横比を指定する。

曲線のある図では、全ページを組む前にその部品だけを試作し、PPTX書き出し→再読み込み→描画で形を確認する。成功した幾何を本番へ使い、試作の成功で最終版の検証を代替しない。

滑らかな曲線はネイティブの曲線・ベジェなどで再現する。書き出し機能で崩れる場合は、書き出し方法やパス定義を修正して再確認する。曲線を折れ線に替えることを、忠実な再現の完了として扱わない。

背景の淡いグラデーションや透明度、矢印の曲率・線幅・矢尻、吹き出しの尾と丸みも再現対象とする。

タイトル、出典、ページ番号などの固定位置は配置ルールで決める。ページ番号は顧客設定の揃え方を保持し、桁数で意図せず位置をずらさない。

### 5. 埋め込んだSVGの表示互換性を確認する

SVG本体と参照関係を確認し、必要な書式の正規化は形状を変えずに行う。

SVGを埋め込む場合は、同じSVGを描画した有効なPNG代替画像も用意し、PPTX内の代替画像として正しく関連付ける。空の1px画像で代用しない。

代替PNGは拡張子やヘッダーだけでなく全画像をデコードし、破損・空白・欠け・不適切な白背景がないことを確かめる。ライブラリが自動生成したPNGも対象にする。SVG対応環境で見えたことだけで、代替PNGの成功を推定しない。

[機械検査スクリプト](../scripts/audit_pptx.py)で最終PPTXの媒体・参照関係・接続を確認できる。破損や代替PNGの不良があれば正規素材から修復し、修復後のPPTXを再読み込みする。修復前のプレビューや検証記録を最終版の証拠にしない。

SVGとして移動・差し替えできることと、内部パーツを編集できることを区別する。図形変換や色変更の対応は実機で確認する。

### 6. 再描画と編集操作で検証する

書き出したPPTXを再読み込みして全ページを描画し、採用画像と同じ表示サイズで比較する。全体のバランスを見た後、文字・図形・アイコン・背景を領域ごとに確認する。

差分は「意図した変更」「修正すべき再現誤差」「使用環境や形式に由来する残存制約」に分ける。意図した変更を再び元に戻したり、再現誤差をデザイン改善と呼んで済ませたりしない。

位置・大きさ・改行・要素の欠落を先に修正し、その後に曲線・角丸・色の濃淡・透明度・細部を詰める。比較には必要に応じて並列表示や重ね合わせを使うが、文字の描画差などを含むため画像差分の数値だけで合否を決めない。

曲線、角丸、SVG、透明部分が書き出し後にも保持されることを確認する。データ内で指定できたことと、画面で再現されたことは分けて検証する。

実際のPowerPointと納品先のプレビューでも確認し、環境による差を記録する。実機確認できない場合は未確認と明記する。

文字変更、部品の移動・削除・差し替えを試し、二重の文字や背景の残像が出ないことを確認する。

修正後は影響箇所を再確認し、元素材・旧版を残して新しい版として保存する。

### 検証結果を添えて納品する

PPTXとプレビュー画像に、編集可能な範囲・画像として残る部分・意図した変更・残存する差分・未確認事項を添えます。結果は[検証・納品記録](verification.md)にまとめます。

未実施の検証は未確認のまま、該当なしには理由を記録します。実機確認や自動実行は利用環境に依存し、このキットを読んだだけで完了したとは扱いません。

## 判断の補足

ブランドルールは「必須の固定条件」と「推奨値・目安」に分けます。忠実な再現と別デザインへの改善を同時に行いません。部品記録の正本はJSONまたはMarkdownにできます。表・グラフの編集が必要な場合は、必要な数値・項目を確認し、ネイティブの表・グラフとして再構築します。承認済みの背景・ロゴ素材は再利用します。
