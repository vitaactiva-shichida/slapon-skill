# 構成・メッセージ設計

読み手の問い、答え、根拠を整理してから、ページタイプと図解を選びます。見た目を整える前に「何を伝えるか」と「何で支えるか」を決めます。

**問い → 答え → 根拠 → 示唆 → 強調**

これは考える順序です。必ず5つの箱を描く、全項目を毎ページに表示する、という指定ではありません。原稿・採用済みの構成がある場合は必要な箇所だけ照合します。

| 技法 | 使い方 | 整理前 → 整理後の例 |
| --- | --- | --- |
| **読み手の問いを決める** | 何を知り、何を判断するための資料かを一文にする。問いは制作記録に置き、毎ページに表示する必要はない。 | 整理前   「市場調査をまとめる」   整理後   「次にどの市場を優先するかに答える」 |
| **結論と理由を組み立てる** | 提案・報告では、答えを先に示して理由と証拠へ進む。導入は共有する前提→変化・課題→問いで整理できるが、毎ページを同じ順序や箱にしない。 | 整理前   背景→データ群→最後に提案   整理後   提案→理由→裏付け。探索型の議論では問いから始めてもよい |
| **本文タイトルに読み取りを書く** | 説明・分析ページでは、テーマ名より、このページで分かることを文章にする。数値・期間・断定の強さは本文の根拠に合わせる。提供済みタイトルの変更は依頼の範囲に従う。 | 整理前   「導入状況」／本文：2024年38%、2025年44%   整理後   「導入率は2024年の38%から2025年の44%へ拡大」 |
| **主張と証拠を対応させる** | 主メッセージは原則一つ。その下に複数の理由・数値・条件を置ける。各根拠がどの主張を支えるかを確認する。 | 整理前   「法人が成長を牽引」＋顧客属性だけの表   整理後   法人・個人の売上増分と全体への寄与を示す。根拠がなければ主張を保留 |
| **事実・解釈・提案を分ける** | 何が観測され、そこから何を読み取り、何を提案するかを区別する。原稿にない解釈は提案として扱い、裏付けなしに因果を付け足さない。 | 整理前   売上20%増→顧客集中リスクが上昇   整理後   20%増だけでは集中度は不明。顧客別内訳を確認してから示唆を判断 |
| **比較の条件を揃える** | 同じ項目・単位・期間・定義・順序で比べる。欠測は不明とし、ゼロとみなさない。比較対象の固有条件は別に添える。 | 整理前   A社は価格、B社は機能、C社は導入速度   整理後   全社を価格・機能・導入期間の共通行で比較する |
| **主張に対応する場所を強調する** | 表・グラフの注目行、系列、差分を強調する。比較文脈と条件は保持し、色だけに意味を持たせない。注釈は対象の近くへ置く。 | 整理前   全セルを同じ強さで表示   整理後   全セルを残し、結論を支える列や差分を強調。単位・母数も読める位置に残す |
| **タイトルを通して論旨を確認する** | 本編のタイトルを並べ、前後のつながりと飛躍を確認する。対立する根拠や留保を隠して筋を整えない。 | 整理前   「市場／顧客／戦略」   整理後   「市場は拡大／既存層は伸び悩む／未開拓層の可能性を検証する」 |

例の数値・状況は説明用の仮定です。実際の制作原稿に流用しません。

### ページの役割と原稿を尊重する

- 結論型タイトルは説明・分析・提案ページの基本です。表紙、章扉、エンド、用語集、資料一覧に無理な主張を付けません。データ集やダッシュボードは複数の読み取りを許容します。

- 「1枚1メッセージ」は情報を一つに減らすことではありません。複数の根拠・条件・例外を保持し、主張と補足の階層を明確にします。

- 数字の意味を説明しても、証拠以上に強く言い切りません。相関を因果に変えず、推計・速報・仮説の留保を残します。主張の根拠が不足する場合は不足を記録し、調査や確認が必要な点だけ示します。

- 投影・手元閲覧に合わせて見せる順序を調整します。情報の削除、付録への移動、原稿の短縮は依頼の許容範囲に従い、結論を左右する条件を小さな脚注へ追いやりません。

- 強調・余白・囲みの具体的な見た目は共通デザインシステム（顧客HTMLの該当定義）と[デザイン技法](generation-detail.md)に従います。一般的な作法で顧客の指定を上書きしません。

### 制作前に確認すること

主張が問いに答えているか、証拠が主張を支えるか、解釈を言い過ぎていないか、タイトルと数値・条件が一致するか、強調箇所が読み取りを助けるかを確認します。主張数や出典の有無だけで、論理の妥当性を合格にしません。

判断は[構成の記録](diagram-plan.md)に短く残し、承認済みの原稿や根拠を毎工程で転記しません。PowerPoint化だけの依頼では構成を作り直さず、不整合があれば原稿と照合して扱いを決めます。
