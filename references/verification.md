# 表示・編集の検証と納品

[PowerPoint手順](powerpoint.md)の検証工程と併用する。ファイルが作成できたこと、XMLに値があること、画像と見た目が合うこと、実際に編集できることを分けて確認する。

## 確認する順序

1. 出力したPPTXを再読み込みして全ページを描画する。実際に出力した版を比較対象にし、途中のプレビューで最終版を確認済みとしない。
2. 原稿との照合で、文字・数値・単位・条件・出典・欠落・重複を確認する。図の要素数・接続先・向き・比較条件とタイトルの根拠も照合する。
3. 採用画像と同じ表示サイズで全体と各領域を比較する。位置・サイズ・改行を先に直し、次に線・曲線・角丸・色・透明度・トリミングを確認する。並列や重ね合わせを使い、画像差分の数値だけで合格にしない。
4. 編集用の複製で文字変更、部品移動・削除・差し替え、グループ操作を試す。二重の文字・残像、コネクタの追従、表やグラフの値変更と表示更新を確認する。
5. 埋め込みSVGとPNG代替の対応、画像全体のデコード、透明部分と背景、欠けや空白を確認する。移動・差し替えと内部編集を区別する。
6. 利用できる場合はPowerPoint実機と納品先プレビューでも確認し、環境と差を記録する。利用できなければ未確認とする。修正後は影響箇所を再検証し、共通部品を変えた場合は全対象ページへ広げる。

差分を「意図した変更」「修正すべき再現誤差」「環境・形式による制約」に分ける。必須内容や表示・編集の不具合が残れば修正する。修正できない場合は対象と制約を明示し、完全再現・全編集可能・実機確認済みと表現しない。

## 確認した事実と証拠を対応させる

[進行条件](checkpoints.md)に照らし、状態だけでなく対象ページ・版・操作・結果を記録する。最終PPTXのSHA-256を記録し、再描画・機械検査・編集用複製が同じ版から作られたことを照合する。検証後に編集やパッケージ修復を行ったら対象を新しい版へ切り替え、影響する検証をやり直す。

- **全ページの表示**：最終PPTXを再読み込みしたページごとの画像を残し、採用画像と同じ幅で並列表示または重ね合わせを用意して実際に見る。代表1枚の成功を全ページへ拡張しない。全体、文字、図形・接続、SVG・重なりの順に確認する。
- **編集操作**：納品版から作った複製で、文字変更、部品移動、削除、差し替え、グループ操作を確認する。同じ構造の部品は代表例でよいが、構造が異なる部品は分ける。接続図はノードを端点の変化が見える程度に動かして追従を確認する。画面や操作結果を残し、復元または複製の変更を破棄する。
- **複数行の文章**：同じ書式の一文・段落・ラベルが一つのテキストボックスになっているか確認する。グループを選べたことだけで合格にしない。代表箇所で全文選択・文字変更・改行を操作し、文章をまとめて編集できること、行間と折り返し、周辺の収まりを確認する。
- **実機と書体**：利用可能なPowerPointで全ページを表示し、指定書体が実際に使われているか確認する。アプリが開けたことと全ページを目視したことを分ける。実機がない場合は理由を付けて未確認とし、実施可能な再読み込み・目視比較・機械検査は続ける。
- **未確認の扱い**：移動・削除を試しただけで差し替えや内部編集まで確認済みにしない。「未確認」と書くだけで、実行可能な確認を省略してよいわけではない。解消できない項目は影響と次の確認方法を添え、確認できた範囲に限定して案内する。

最終PPTXの機械検査は次を実行するか、同等の媒体デコード・参照関係・接続先の検査で代替し、結果を残す。Python 3とPillowが必要。依存不足なら合格扱いせず、利用可能な環境で同等の検査を行うか、未確認として理由を残す。

```sh
python scripts/audit_pptx.py /path/to/final.pptx --expected-slides 5 --out /path/to/package-audit.json
```

5は案件の枚数へ置き換える。合格しても原稿の正確さ・視覚的一致・実機での編集は別に確認する。全ページ画像のハッシュと、目視・操作の結果も検証記録へ残す。

## 納品するもの

依頼されたPPTXまたは画像と、対象の全ページプレビューを用意する。取得先、使用版、編集可能な範囲、画像で残る部分、意図した差分、残る制約・未確認環境を短く案内する。案件の[部品記録](parts-record.md)と以下の検証記録を対応させ、原本・採用画像・旧版を保持する。

## 検証・納品記録のひな型

結果は「確認済／要修正／未確認／該当なし＋理由」で記録します。チェックの状態だけでなく、確認したファイル・操作・環境を追えるようにします。同じ結果は対象ページをまとめて記録できますが、全ページを確認した範囲を明示します。

```
案件情報・部品記録：参照先
検証対象：PPTXのファイル・版／対象ページ
比較元：採用画像と原稿の参照先
実施環境：描画ツール・版／PowerPointの版／日時
実機・納品先プレビュー：実施環境または未確認の理由

表示確認：項目 → 状態／対象ページ／証拠・差分
・PPTX再読み込み、全ページ描画、採用画像と同じサイズで比較
・文字・数値・条件・出典の保持、欠落・重複・はみ出し
・構成記録との一致：タイトルと根拠・数値・留保、比較条件、強調箇所（構成の妥当性は記録を参照）
・位置・サイズ・改行・書体・行間・内側余白
・曲線・角丸・矢尻・線幅・接続先
・濃淡・透明度・グラデーション・画像比率と切り取り
・SVGとPNG代替の参照関係、全画像のデコード、空白・欠け・背景
・納品先プレビューとの表示差

編集確認：操作 → 状態／対象部品・ページ／結果
・文字変更、改行と収まり
・部品の移動・削除・差し替え、下から重複した文字や残像が出ない
・グループ単位の操作、移動した図形とコネクタの接続
・SVGの移動・差し替えと、内部パーツの編集可否
・表・グラフの数値編集（該当する場合）

差分と修正：
対象 → 意図した変更／再現誤差／環境・形式の制約 → 対応 → 再確認結果
修正後の検証範囲：影響箇所／共通変更なら全対象ページ

納品版：PPTX・全ページプレビューのパス／版
編集可能な範囲・画像として残る範囲：部品記録を参照し要点のみ
残る差分・未確認事項：
完了判断：条件を満たした根拠、または未完了の理由と次の対応
原本・旧版・使用素材・制作記録の保存先：
```
