# 工程ごとの証拠と進行条件

開始時に現在の工程とユーザーが求める停止位置を特定し、依頼範囲に必要な行だけを使う。既存の制作記録を参照し、同じ内容を別ファイルへ重複転記しない。依頼された制作や実施可能な確認を、手順説明だけで終えない。

| 工程 | 次へ進むために実物で確かめること | 記録に残す証拠 |
| --- | --- | --- |
| 原稿・構成 | 読み手、主張、正しい原稿と条件、情報量、ページ構成、図解の意味が決まる | 対象ページ、原稿・出典、構成の参照先、確定事項。要確認事項が残れば依存作業を待つ |
| パターン選定 | カタログを検索し、候補のPNG/SVGを取得して実際に表示する | パターンID・版・取得元、選んだ理由、変える要素数・配置。見本の文章や形を正解として固定しない |
| 画像生成・採用 | 原稿・顧客の文字入り見本・必要な図解参考を生成ツールへ実添付し、出力全ページを見る | 実入力、添付一覧、出力パスと寸法、確認結果、採用されたページ・版と指示。プロンプト作成や添付予定だけで生成済みにしない |
| 再構成範囲 | 採用画像から、標準部品・SVG・画像の範囲と編集単位を先に決める | 部品記録、SVG対象と理由、別テキストのラベル、A/B/C。一枚のスライドを先にSVG化しない |
| 素材・PPTX | 必要なSVGだけを用意し、正規ロゴと有効なPNG代替、必要なネイティブ図形で組む | 素材原本・派生版、曲線試作の再読み込み結果、PPTX、意図した差分。できたことと検証済みを分ける |
| 検証・納品 | 最終PPTXの全ページ再描画、原稿照合、同サイズでの画像比較、複製での編集操作、利用可能なら実機表示 | 最終ファイルのハッシュ、全ページ画像と比較表示、機械検査、操作・部品・結果・環境、制約。詳細は[検証手順](verification.md) |

## 省略や代替を認めないもの

- 画像案を求められた工程をSVG/HTMLの作図で代替する、または採用前に編集部品制作へ進むこと。対象の採用・一括進行がすでに明示されている場合は聞き直さない。
- ヘッダー・タイトル・フッターまで一枚のSVGにまとめる、完成画像を背面に残す、文字入りSVGを置いて「文字を編集可能」とすること。
- 代表ページだけの確認を全ページの確認に拡張すること。編集操作は同じ構造なら代表例でよいが、表示確認は全ページが対象。
- 旧版・試作・修復前のプレビューを最終納品版の証拠にすること。XMLの値、コードの正常終了、ファイルの存在だけで見た目や編集操作を合格にすること。
- 時間・費用・トークンを節約するために、残っている必要作業を自己判断で打ち切ること。ツールや依存が利用できない場合は、その制約を特定し、できる確認を続ける。

## 完了と案内の範囲

記録には「確認済／要修正／未確認／該当なし＋理由」、対象ページ・版・証拠・次の対応を付ける。未確認を合格や該当なしへ付け替えない。記録を書いたこと自体は実施の証拠ではない。

未確認でも使える成果物がある場合は、確認できた範囲と制約を示してレビュー用として渡せる。ただし、必要な確認が残る状態を「検証完了」「全編集可能」「実機確認済み」と呼ばない。ユーザーが限定範囲を了承した場合はその範囲を記録する。別の未確認項目まで了承されたと解釈しない。

スキル本文だけでAIの省略を技術的に防止できるわけではない。成果物・ハッシュ・機械検査・実際の表示と操作を対応させ、後から省略を検出できる状態にする。機械検査の合格も目視・操作の代わりにはしない。
